# 知选 产品需求文档

## 1. 产品定位

知选是一个按预算导购的购物 App：用户用一句话说出用途和预算，知选从真实在售商品里挑一件，或者按总预算配一整套，并把“为什么是它、一共多少钱、在不在预算内”讲清楚。

- **目标用户**：知道要花多少钱、但不想自己逐个比参数的人；一次要买好几样、需要把总价控制住的人（开学、出差、送礼、换新）。
- **核心承诺**：推荐结果的合计（含按店铺合并的运费）不超过用户的总预算；只有在所有费用已知、报价未过期时才说“在预算内”。
- **差异点**：不是单品比价，而是“总预算下的整套最优组合”；AI 负责听懂、规划、找准、讲清，预算由确定性求解守住。

## 2. 核心场景

| 场景 | 用户说法示例 | 知选的结果 |
|---|---|---|
| 单件按预算挑 | “通勤用的降噪耳机，800” | 一款最适合的 + 两款备选（便宜一点 / 好一点），附理由 |
| 多件按总价配 | “吹风机和电动牙刷，一共600” | 两件联合求解，合计在预算内 |
| 只说目标 | “下周出差一周，想配点数码装备，1500以内” | 自动拆成充电宝、耳机、键盘等，按总价配齐 |
| 带场景和人群 | “宿舍用的吹风机，别太吵”“送经常跑步的男朋友” | 按场景精排，优先更安静 / 更适合运动的款 |
| 还没想好预算 | “想买个台灯，还没定预算” | 按价位展示“多数人会选 / 想省一点 / 想要更好的”，一句话问预算 |
| 对比同类 | 商品页“帮我对比一下同类商品” | 对比表 + 怎么理解差异 + 首选 / 备选 |
| 连续修改 | “预算再多给一百五”“去掉吹风机”“锁定这款”“买两个” | 在同一个购物车上重新求解，不动锁定的商品 |

## 3. 功能范围

### 3.1 页面

- **首页**：搜索（像需求的句子直接进入导购）、品类入口、推荐商品流、悬浮“问知选”入口。
- **分类 / 搜索结果**：排序（综合、价格）、商品卡（来源平台、价格日期）。
- **商品详情**：图集、卖点、规格参数、价位相近商品、问问知选（对比同类 / 这款适合我吗 / 怎么选）、收藏、加入购物车、立即购买（跳转原平台）。
- **问问知选**：页签「知选｜商品｜攻略｜体验」。
  - 知选：对话；发送后实时展示思考过程（读取需求、理解场景、拆解目标、召回商品、语义匹配、场景精排、组合求解，每步带真实数量与依据，完成后折叠为“已思考 · 用时 N 秒”）；回复包含推荐商品行（加入购物车 / 立即购买 / 换这款）、为什么这么挑、选购攻略卡片、小提示、猜你想问。
  - 商品：当前话题相关品类的商品流。
  - 攻略：品类选购要点与避坑提醒。
  - 体验：真实用户使用体验笔记（标题、作者、赞藏、摘录，链接回原文）。
- **购物车**：总预算、合计与预算关系（一句话）、数量、锁定、换一款、整套 / 单品视图。
- **我的**：登录 / 注册、收藏、历史对话、账号安全、协议与隐私。

### 3.2 预算约束（不可被任何环节绕过）

| 约束 | 规则 |
|---|---|
| 金额 | 全程整数分 |
| 总价 | 多件联合求解，合计（含运费）≤ 总预算 |
| 运费 | 按平台公开规则按店铺合并；规则不明写“运费以平台为准”，不补 0、不标在预算内 |
| 报价时效 | 报价超过 14 天只作参考，不能确认预算 |
| 硬条件 | 满足 / 不满足 / 未知三态，商品页没写的不算满足 |
| 用户决定 | 锁定的商品不替换；无解时只给可选调整，不自动加预算或解锁；换视图不改购物车和预算 |
| 金额理解 | 单价与总价分开识别，相对调整（“再加一百”）按原预算增减，多个金额冲突时追问 |

### 3.3 预算的呈现

预算是承诺，不做成需要用户操作的筛选器：界面不出现预算筛选卡片和“在预算内”徽标，只在回复里用一句话交代（“合计 ¥399，在预算内，还留了 ¥151”）。未给预算时用价位浏览自然引导，而不是让用户点选金额。

### 3.4 AI 在链路中的职责

| 环节 | AI 做什么 | 程序把关 |
|---|---|---|
| 理解与规划 | 读出场景、人群、偏好；只说目标时拆出品类；口语改写成标准需求 | 改写结果交回规则解析；预算只认原话数字；品类只取商品池里有的 |
| 语义召回 | 用场景与商品语义向量的相似度提升贴合场景的候选 | 只作用于已通过品类、硬条件、单价过滤的候选 |
| 场景精排 | 给预算内的前几名候选打 0–3 场景匹配分并写依据 | 只认展示过的商品；加减分有上限；最终由求解器按总预算定稿 |
| 讲解 | 推荐理由、差异解读、小提示、追问；商品问答 | 数字须出自商品数据；禁用无依据宣传词；未判定在预算内不得声称 |

触发方式：带场景、人群、偏好的新需求，只说目标的需求，以及规则看不懂的口语，会走理解规划、语义召回和场景精排；只有品类和预算、或改购物车的话由规则直接处理，模型只负责讲解。用户能实时看到每一步在做什么、用了哪些数据：思考过程里的“理解场景 / 目标规划 / 语义召回与精排”，以及商品上的“契合场景”依据。

AI 不可用时自动退回规则与参数排序，功能完整、结论不变。

## 4. 数据

- **商品池**：小米商城、Apple 官网、戴森官网的公开页面，299 个 SKU、14 个品类，人民币当日标价与采集时间，参数只取页面写明的内容。
- **体验笔记**：小红书各品类真实使用体验，只保存标题、作者、点赞收藏数、话题和 50 字以内摘录。
- **语义向量**：每个 SKU 一条，由标题、品牌、品类、参数、卖点与主要规格生成。

## 5. 非目标

- 不在站内下单、支付或代购：购买在原平台完成。
- 不做目标价自动下单、定时购买：商品价格是采集快照，不具备实时成交条件。
- 不展示无依据的宣传信息：销量、好评率、全网最低、历史最低等。

## 6. 质量要求与验收

| 项目 | 标准 |
|---|---|
| 预算硬规则 | 多轮对话基准 12 个硬规则组 100% 通过（当前日期与 30 天后两种时钟） |
| AI 链路 | 端到端评测全部通过：预算识别正确、规划品类齐全、不越预算、无禁用词、单次响应 ≤ 25 秒 |
| 界面文案 | 违禁词扫描通过；接口密钥不出现在任何发布文件中 |
| 端到端 | 浏览器测试覆盖首页、详情、导购、购物车、注册登录、桌面与手机宽度 |
| 可访问性 | 中国大陆网络可直接打开（新加坡区部署）；海外可访问 |

## 7. 指标

- 导购完成率：发起导购的会话中，得到推荐并点击“加入购物车”或“立即购买”的比例。
- 预算贴合度：推荐合计 / 用户总预算（关注过低与无解的比例）。
- 追问率与追问后完成率：需要澄清的轮次占比，以及澄清后得到推荐的比例。
- 规划采纳率：目标型需求中，用户保留 AI 规划品类的比例。
- 对比后决策率：发起对比后选择首选或备选的比例。
